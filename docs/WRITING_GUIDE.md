# 집필 지침

## 독자

개발자가 아닌 기획자·운영자·관리자도 이해할 수 있어야 한다. 기술 용어는 먼저 일상적인 비유로 설명하고, 그 다음 정확한 용어를 병기한다.

## 모든 장의 구성

1. 한 문장 요약
2. 실제 업무 상황
3. 핵심 개념 표
4. 따라 하기 또는 점검표
5. 실패 사례와 안전한 대안
6. 장 요약과 공식 출처
7. 장의 개념을 설명하는 고유 도식 1개 이상

## 최신성 원칙

- MCP 사양 버전과 확인 날짜를 표시한다.
- 제품별 설정 화면은 변할 수 있으므로 공식 문서 링크를 함께 둔다.
- 표준 문서, 제품 문서, 실험·의견을 구분한다.
- 키·토큰·개인정보는 예시에 절대 실제 값을 넣지 않는다.

## 안전 원칙

MCP 연결은 기능 소개보다 권한 경계와 실패 처리를 먼저 설명한다. 도구를 연결했다고 실행 권한을 자동으로 부여하는 것으로 쓰지 않는다.
